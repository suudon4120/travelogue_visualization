## 概要 (Overview) 📝

このプロジェクトは、旅行記のテキストデータから旅行者の体験（訪問地、感情）を抽出し、地図上にインタラクティブに可視化するシステムです。自然言語処理と地理空間情報技術を組み合わせ、個人の主観的な旅行体験を直感的に分析することを目的としています。

## 背景・目的 (Background) 💡

個人の旅行体験はSNSやブログに大量に蓄積されていますが、その多くは文章のままで、体系的な分析が困難でした。本研究では、特に旅行者の感情や体験に焦点を当て、LLMによる感情分析を用いることで「どの場所で、どのような感情が生まれたか」を視覚的に捉え、ウェルビーイング向上に繋がる旅行プランニングへの応用を目指します。

## 主な機能 (Features) ✨

### ✅ 実装済みの機能
- [x] 旅行記テキストからの地名抽出機能
- [x] 抽出した地名に対する緯度経度情報の付与
- [x] 各訪問地におけるテキストの感情分析（ポジティブ/ネガティブ判定）
- [x] 訪問地の系列と感情価を地図上にマッピングして可視化（HTML出力）

---
### 🛠️ 開発中の機能
- [ ] **可視化結果の自動評価**: 地図上に可視化されたhtmlファイルから，訪問地での行動と感情価の関係を自動評価する．
- [ ] **旅行記の反実仮想シミュレーション**: 可視化分析の結果に基づき，ネガティブな体験をマスクし，LLMによって前後の文脈から起こり得たポジティブな体験を生成する．これにより，旅行体験の可能性を探求し，よりよい旅行体験をデザインする．

## 技術的な挑戦・工夫した点 (Challenges & Highlights) 🚀

このプロジェクトの開発において、特に以下の点に注力しました。

* **情報の可視化**: 抽出した大量の情報を，いかに直感的に地図上へ表現するかが課題でした．そこで，30種類以上の「行動タグ」を定義し，アイコンと感情スコアに基づくヒートマップを組み合わせることで，複雑な旅行体験を人目で理解できるUIを設計・実装しました．
* **位置情報の特定**: 旅行記の曖昧な地名表現から，正確な緯度経度を特定することは困難でした．そこで，LLMが大まかな地域を推測し，その情報をヒントにgeopyが座標を特定するという，独自の二段階推定プロセスを考案しました．これにより自由記述テキストからでも高い精度でのジオコーディングを実現しました．
* **三段階のフォールバックによる位置情報特定の安定化**: 自由記述の地名から座標を特定する際，単一の手法では失敗することが多々ありました．そこで，①geopy→②国土地理院API→③LLMによる推定，という三段階のフォールバック処理を実装．これにより，多様な入力に対しても座標取得の成功率を高め，データ欠損の少ない頑強なシステムを実現しました．
* **キャッシュ機能による処理の中断と再開**: 座標推定には長時間かかるため，中断時の手戻りを防ぐ「チェックポイント機能」を実装しました．処理済みのデータを定期的にキャッシュとして保存し，万が一プロセスが中断しても，その地点から処理を再開できる設計にしました．これにより，時間と計算資源の無駄をなくし，安定したデータ処理を実現しました．

## 使い方 (Usage / Setup) ⚙️
このプロジェクトには、2つの異なる実行モードが用意されています。目的に応じて使い分けてください。

### 2つの実行モードについて

| モード | 主要スクリプト | 特徴 | こんな時に便利 |
| :--- | :--- | :--- | :--- |
| **リアルタイム処理** | `travelogue.py` | 実行後すぐに結果の地図が生成される | 少量のデータですぐに結果を確認したい時、デバッグ時 |
| **バッチ処理** | `travelogue_create_batch.py` | OpenAI APIのコストを**50%削減**できるが、結果取得に最大24時間かかる | 大量の旅行記データを一度に分析したい時 |

---

### セットアップ (共通)

どちらのモードを実行する前にも、以下のセットアップが必要です。

1.  リポジトリをクローンし、ディレクトリに移動します。
    ```bash
    git clone [https://github.com/suudon4120/travelogue-visualization.git](https://github.com/suudon4120/travelogue-visualization.git)
    cd travelogue-visualization
    ```
2.  必要なライブラリをインストールします。
    ```bash
    pip install -r requirements.txt
    ```
3.  `.env`ファイルを作成し、OpenAIのAPIキーを設定します。
    ```
    OPENAI_API_KEY="sk-..."
    ```

---
### モード1: リアルタイム処理

すぐに分析結果の地図を生成したい場合の方法です。

1.  分析したい旅行記のファイル番号を記載したテキストファイル（例: `input.txt`）を用意します。
2.  以下のコマンドでスクリプトを実行します。
    ```bash
    python travelogue.py
    ```
3.  実行後、カレントディレクトリに`visited_places_map_emotion_....html`というファイルが生成されます。

---

### モード2: バッチ処理 (APIコスト削減)

大量のデータを処理し、APIコストを抑えたい場合の方法です。OpenAIのBatch APIを利用します。

#### ステップ1: バッチジョブ用のファイルを作成

`travelogue_create_batch.py`を実行し、バッチ処理を開始します。

1.  分析したい旅行記のファイル番号を記載したテキストファイル（`input.txt`）を用意します。
2.  以下のコマンドでスクリプトを実行します。
    ```bash
    python create_batch_job.py
    ```
3.  実行後、`"id": "batch_..."`のように**バッチID**が返されるので控えておきます。

#### ステップ2: 結果の取得

バッチ処理は最大24時間かかります。
`travelogue_process_batch.py`を実行し、結果を取得します。

1.  以下のコマンドでスクリプトを実行します。 
    ```bash
    python travelogue_process_batch.py
    ```
2.  控えておいたバッチIDを入力すると結果がダウンロードされ，自動的に可視化処理が開始します．
3.  実行後，カレントディレクトリに`visited_places_map_emotion_batch....html`というファイルが生成されます。
